# ADR 0002: VNC のデスクトップでウィンドウマネージャー (wm2) を使わない

- 状態: [ADR 0003](0003-icewm.md) で置き換え（2026-11-03 採用、同日に置き換え）
- 関連: ADR 0001（Wine 10 と TightVNC）、RUNBOOK「MT の固まりの切り分け」

## 背景

- atst は VNC（TightVNC）のデスクトップで、ウィンドウマネージャーとして wm2 を起動していた（`~/.vnc/xstartup` の `x-window-manager &`）。
- 本番の VPS で、MT4 の UI が固まる事例が 2026-10 に複数回あった。固まっている間は main thread と wineserver の CPU が張り付いていた。ターミナル欄の「記事」タブが原因と見ていた。
- 2026-11-03、検証用の VM（GCE e2-micro、Ubuntu 24.04 minimal、Wine 10.0、MT4 build 1492）を手順書どおりにまっさらな状態から作り、次を確かめた。
  - wm2 の下では、MT4 の UI が固まった。きっかけは、デモ口座作成の「完了」と「ツール」メニューのクリックの 2 回。固まっている間は terminal.exe・wineserver・Xtightvnc の CPU が張り付いていた。
  - 固まった状態のまま wm2 のプロセスを止めると、MT4 はすぐに動き出した。Xtightvnc の CPU は 23% から 0.3% に下がった。
  - wm2 の下では、MT4 の窓の中のクリックが (+25, +8) ピクセルずれた（RUNBOOK の「クリックが数ピクセルずれる」）。
  - wm2 を起動しない環境では、インストール、デモ口座作成、メモリ削減、EA と監視 EA の配置、再起動後の `@reboot` での自動起動まで、固まらずに動いた。「記事」タブを開いたままでも、起動と操作に問題はなかった。クリックのずれも無かった。

## 決定

1. VNC のデスクトップでウィンドウマネージャーを起動しない。`templates/xstartup` から `x-window-manager &` を外し、`wm2` パッケージを入れない。
2. 既存の環境は、インストーラを再実行したときに `~/.vnc/xstartup` の `x-window-manager &` の行（旧テンプレートが書いた行と完全に一致するもの）をコメントにする。元のファイルは `~/.vnc/xstartup.bak.<日時>` に残す。それ以外の xstartup（独自に書き換えたもの・シンボリックリンク）は変えない。インストーラが VNC を起動し直したときに効く。
3. インストーラを再実行しない既存の環境の手順は、RUNBOOK に書く。動いている wm2 は、MT を動かしたまま止めてよい。

## 結果

- MT の窓には枠が無く、動かせない。MT は画面いっぱいに表示されるので、操作には困らない。ダイアログやメニューは普通に出る。
- クリックがずれなくなる。
- 入っている wm2 のパッケージは消さない（使わないだけ）。

## 見直しの条件

ウィンドウマネージャーが要る場面（窓を動かす必要があるなど）が出たら、wm2 以外の軽いウィンドウマネージャーを、上の固まりの再現手順で確かめてから選ぶ。
