# 契約テンプレ: シェルスクリプト / CLI

対象: `check_*.sh` / `setup_*.sh` / `install_required_for_mt.sh` / `mtctl.sh` / `report_image.sh` / `draw_graph.sh` / `wrapper.sh` などの実行可能スクリプト。**AI や cron が引数を組み立てて呼ぶ**ため、「呼び出し側が指定できる軸」と「副作用の全列挙」が契約の中心になる。

## 記入項目

| 項目 | 書き方 |
|---|---|
| 役割 | このスクリプトが 1 文で何をするか |
| 引数 | 位置引数・オプションを列挙。**呼び出し側が指定できる軸**を明示（列挙に無い軸＝固定）。MT 名は前方一致で解決される点に注意 |
| 標準入力 | stdin から読むか（例: `draw_graph.sh` は CSV を stdin で受ける）。読むなら形式 |
| 消費する環境変数 | `WINEARCH` / `WINEPREFIX` / `WINEDLLOVERRIDES` / `DISPLAY` / `ATST_*`（`common.sh` 由来の設定）/ `TARGET` 等。**必須か任意か、既定値**も書く |
| 依存する外部コマンド | `wine` / `wineserver` / `vncserver` / `vncsnapshot` / `gnuplot` / `curl` / `wget` / `crontab` / `apt` / `sudo` / `gh` など。無いときの挙動（中断するか） |
| 副作用（**全列挙**） | 書き込むファイル・ディレクトリ / `apt` によるパッケージ変更 / `crontab` 変更 / `wine`・MT プロセスの起動/停止 / 外部 HTTP（winehq・MQL5・ブローカー）/ **LINE 送信** / systemd サービス操作。**本番VPS に不可逆な影響があるものは明記** |
| 終了コード | 0 / 非 0 の意味。拒否（前提不成立）と失敗を区別するか |
| 標準出力 | 返す形式（プレーン / 構造化）。**LINE トークン・auth.txt の値・署名付き URL・口座情報を出さないこと** |
| 冪等性 | 同じ引数で 2 回実行したときの挙動（再実行で壊れないか・二重登録しないか） |
| クロスディストロ前提 | 対応ディストロ（Ubuntu 20.04/22.04/24.04・Debian 11/12）で分岐・パッケージ差をどう吸収するか。systemd / 非 systemd の両対応要否 |
| 本番影響 | このスクリプトを本番VPS で実行することが建玉・決済・MT 稼働に影響するか（= ユーザー承認が要るか） |

## 記入テンプレ

```markdown
### `<script>.sh [<args>]` — 新規 / 改修

- 役割: <1 文>
- 引数: <位置引数 / オプション>（指定できる軸: <...>。これ以外は固定）
- 標準入力: <読む形式 / 読まない>
- 消費する環境変数: <VAR>（必須/任意、既定値 <...>）
- 依存コマンド: <cmd1> / <cmd2>（無いとき: <中断 / 警告して継続>）
- 副作用:
  - ファイル: <書き込み先パス>
  - パッケージ: <apt install/upgrade するか>
  - crontab: <変更するか>
  - MT / wine: <start/stop/kill するか>
  - ネットワーク: <アクセス先 URL>
  - LINE 送信: <するか>
  - systemd: <サービス操作>
- exit: 0 = <成功> / 1 = <前提不成立（理由を stderr）> / 2 = <失敗>
- stdout: <形式>（出さないもの: LINE トークン / auth.txt / 署名付き URL / 口座情報）
- 冪等性: <2 回目の挙動>
- クロスディストロ: <分岐の要点 / systemd と非 systemd の扱い>
- 本番影響: <あり（ユーザー承認必須） / なし（読み取りのみ）>
- 改修の場合の差分:
  - 現契約（コードから抽出）: <現状の引数・副作用>
  - 変更点: <追加 / 削除した軸・副作用>
  - 後方互換: <破壊あり（影響: cron 定義 / 呼び出し元 N 件）/ なし>
```

## 観察可能な AC への落とし方

契約 1 行 → 検証 1 本 → AC 1 行、の対応を保つ。本番VPS でしか判定できない AC は確認手順を併記する（ローカルでは判定不能と明記）。

| 契約 | 観察可能な AC |
|---|---|
| 構文の健全性 | `bash -n <script>.sh` がエラーなく通る |
| 引数不足で拒否 | `引数なしで実行すると exit 非 0・Usage を stderr に出す`（`run; echo $?`） |
| 副作用の限定 | `--dry-run 相当や前提未成立時に apt/crontab/mtctl を呼ばない`（`grep` で呼び出し箇所がガードされていること） |
| stdout に秘匿情報を出さない | `出力に LINE トークン・署名付き URL のクエリ（token= / sig= 等）が含まれない` |
| 冪等性 | `2 回実行しても crontab 行が重複しない`（本番は承認後にデモ/確認） |
| クロスディストロ | `systemd と非 systemd の分岐を両方通る`（`grep` で両分岐の存在） |

**書いてはいけない AC**: 「正しく動作する」「適切に処理される」。反証条件が無い AC は Phase 1 の QA 視点が block する。
